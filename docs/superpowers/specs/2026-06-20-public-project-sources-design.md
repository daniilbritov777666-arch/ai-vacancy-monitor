# Расширение публичных источников разовых проектов

## Цель

Увеличить число подходящих разовых IT-заказов для автономного агента за счет российских публичных площадок, доступных без Telegram и пригодных для выплат на российские реквизиты.

## Подтвержденные источники

### Freelance.ru Tasks

- URL: `https://freelance.ru/task`.
- Страница содержит свежие задания, постоянные URL `/task/view/<id>`, даты и бюджеты.
- Адаптер работает через обычный HTTP и HTML-парсер.

### Pchel.net Jobs

- URL: `https://pchel.net/jobs/`.
- Страница содержит свежие проекты, постоянные URL с ID, категории и бюджеты.
- Адаптер работает через обычный HTTP и HTML-парсер.

## Источники в режиме проверки доступности

### Kwork Projects

Публичная страница доступна, но список проектов загружается клиентским JavaScript через недокументированный внутренний интерфейс. Первая версия не зависит от закрытого endpoint и не имитирует авторизованный браузер. Health-probe фиксирует доступность страницы и изменение сигнатуры. Подключение реальных проектов возможно отдельным слоем через официальные email-уведомления или документированный API, если он появится.

### Workzilla Tasks

Публичный URL содержит примеры заданий, а не подтвержденную ленту свежих заказов. Первая версия не импортирует эти записи. Health-probe контролирует страницу; реальные задания подключаются позднее через официальный аккаунт или email-уведомления.

## Архитектура

Новый модуль `public_sources.py` содержит интерфейс адаптера и реестр источников. Каждый адаптер получает HTML, валидирует сигнатуру страницы и возвращает существующие объекты `Post`. Текущий `run_monitor` остается единым конвейером дедупликации и фильтрации.

В `Config` добавляется `PUBLIC_PROJECT_SOURCES`. По умолчанию включены `freelance_ru` и `pchel`; `kwork_probe` и `workzilla_probe` выполняют только проверку доступности. Источники опрашиваются существующим локальным циклом не чаще одного раза в пять минут.

## Нормализация

Для каждого проекта сохраняются:

- стабильный `post_id` с именем площадки и ID проекта;
- канонический URL;
- заголовок и описание;
- дата публикации в исходном часовом поясе;
- бюджет в тексте, чтобы существующий AI-анализ определял цену;
- открытый email, только если он явно опубликован в карточке проекта.

Посты без доказуемой даты не допускаются к автоматическому отклику. Существующий `AUTO_OUTREACH_MAX_AGE_HOURS` ограничивает свежесть проекта.

## Контакт и отклик

В `CustomerContact` добавляется канал `email`. Email извлекается только из открытого текста задания; скрытые контакты, обход авторизации и сбор персональных данных не используются.

Новый `SMTPOutreachClient` отправляет персональный первый отклик, если настроены `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD` и `SMTP_FROM`. Используется TLS, таймаут и один `Message-ID` на заказ. Действуют существующая дедупликация и дневной лимит автооткликов, максимум один email на проект.

Если официальный канал или открытый email отсутствует, заказ получает статус `contact_unavailable`. Агент не создает Telegram-кнопки, не ждет пользователя и не пытается обходить формы площадки.

## Ошибки и наблюдаемость

- Ошибка одного источника не останавливает остальные.
- Пустой результат при изменившейся HTML-сигнатуре считается ошибкой парсера, а не корректным нулем.
- Последний health-report записывается в `orders/reports/public_sources_health.json`.
- Повторяющиеся ошибки источника агрегируются и попадают в периодический Telegram-отчет агента.
- SMTP-ошибка переводит конкретный заказ в `send_failed`; повторная отправка в том же цикле запрещена.

## Тестирование

- HTML fixtures для Freelance.ru и Pchel.net проверяют ID, URL, текст, дату и бюджет.
- Fixtures Kwork и Workzilla доказывают, что динамические или демонстрационные записи не импортируются как живые проекты.
- Контрактные тесты обнаруживают изменение обязательных CSS-селекторов.
- Интеграционные тесты проверяют общий monitor pipeline, дедупликацию и независимость ошибок источников.
- SMTP-тесты проверяют TLS, заголовки, дневной лимит, один отклик на проект и отсутствие отправки без открытого email.

## Не входит в слой

- браузерная автоматизация личных кабинетов;
- обход CAPTCHA и антибот-защиты;
- скрытые или недокументированные API;
- Telegram userbot;
- повторные холодные сообщения одному заказчику.
