# Автономная проверка качества результата

## Цель

Перед каждой автоматической сдачей проверять созданные файлы локальными правилами и AI-рецензией. Не отправлять заказчику результат, который не прошел проверку, и не запрашивать ручное подтверждение.

## Поток

1. Агент создает пакет в `execution/generated/` и сообщение в `outbox/delivery_message.md`.
2. Локальная проверка проверяет наличие и размер файлов, пустые результаты, синтаксис Python/JSON/CSV, утечки секретов и наличие инструкции для программных проектов.
3. AI-рецензент сопоставляет исходное ТЗ, переписку и список файлов; возвращает структурированный вердикт `passed`, замечания и инструкцию исправления.
4. При ошибках агент передает замечания генератору и полностью заменяет пакет результата.
5. Допускается две автоматические попытки исправления после первоначальной проверки.
6. После успешной проверки создается `quality/latest.json`, и существующий канал автосдачи отправляет сообщение заказчику.
7. После двух неудачных исправлений заказ получает статус `quality_failed`; создается отчет, отправка блокируется, Telegram получает только уведомление без кнопок согласования.

## Границы безопасности

- Проверка не запускает непроверенный клиентский код и shell-команды.
- Python проверяется через `ast.parse`, JSON через `json.loads`, CSV через стандартный `csv`.
- Секреты, приватные ключи и заполненные token/password-переменные блокируют сдачу.
- Ошибка или недоступность AI-рецензента считается непрошедшей проверкой, а не разрешением на отправку.
- Старый `delivery_approval_requested.json` не используется в автономном режиме.

## Хранение

- `quality/attempt-001.json` и последующие файлы содержат результаты каждой проверки.
- `quality/latest.json` содержит последний вердикт.
- `quality/quality_failed.json` фиксирует окончательную блокировку.
- В `state.json` используется новый статус `quality_failed`.
